# Working in this repository

Instructions for AI coding agents (Claude Code, Codex, and others) and for humans working the
same way. Read all of it before changing anything.

## The project

EECE 503P/798S course project (Fall 2026) by Karim Assi and Jad Harakeh: an agent that analyzes a
user's longitudinal Fitbit data and reports trends, changes and relationships. **Every claim the
agent makes must be backed by a computed statistic** (an `Evidence` record) that the user can
inspect. The course grades evaluation, reliability, security, AgentOps and engineering practice,
and bonus credit needs *evidence of use*, so process matters as much as code.

**Start with [docs/status.md](docs/status.md)**: the objective, what works, the local setup
(including the Google Cloud project), the data on disk, decisions so far and what is next. The
agent and its evaluation are the priority.

| Path | Contents |
|---|---|
| `backend/` | Python 3.12+ package `app`: Takeout ingestion (`app/ingest`), live Google Health sync (`app/sync`: sign-in, API client, mapping, `python -m app.sync`), database (`app/db`, migrations in `backend/migrations`), deterministic analysis tools returning `Evidence` (`app/analysis`), the agent (`app/agent`: LLM layer, router, experts, verifier, guard), accounts (`app/auth`, `python -m app.auth`), confirmed logging and Google writes (`app/actions`), the API (`app/api`), synthetic data with planted effects (`app/synthetic.py`) |
| `mobile/` | Expo (SDK 58) + Expo Router + TypeScript app for iOS, Android and web |
| `docs/` | `status.md` (where the project is), `costs.md` (API budgets, cost per request, spend log), `product.md` (what the app does and why), `architecture.md` (settled design), `agent-actions.md` (confirmed food and workout logging), `teams.md` (weekly team reports for a supervisor, and their privacy rules), `workouts.md` (workout types, the metrics each kind gets and their Google fields), `ui-plan.md` (the agreed app and UI plan, step by step), `metrics.md` (every daily metric, its Takeout and API source, and how it was verified), `roadmap.md` (plan to the demo), `experiments.md` (every real run: what it tested, showed and changed) |
| `.github/workflows/` | CI: `backend` and `mobile` jobs, both required on `main` |
| `eval/` | evaluation sets and scripts that call paid APIs on purpose (never run in CI) |
| `docker-compose.yml` | local Postgres on port 5433 |

The app talks to the backend only through the contract in `mobile/src/api/types.ts`. Until an
endpoint exists in the backend, the app uses the in-memory mock in `mobile/src/api/mock.ts`.

## Rules that are never broken

- **Personal health data never enters git.** The repo is public. `Takeout/`, `data/`, `*.zip`
  and `.env` are git-ignored; keep it that way. Test fixtures and mock data use **made-up
  values**; only headers and formats may be copied from a real export. Before every commit, check
  the diff for real values, personal paths and secrets.
- **Secrets stay local.** The OAuth client ID and secret, `FA_TOKEN_KEY`, `FA_OPENAI_API_KEY` and
  `FA_TYPESAFE_API_KEY` live only in `.env`; the Google sign-in in `data/google_token.json`. Never print, log or paste tokens, and never print personal health
  values in commands, PRs or chat: report aggregates (counts, agreement rates).
- **Paid APIs cost real, limited money** (about $5 each on OpenAI and Jev). Tests and CI never call
  them; real runs only when model behaviour changed, one or two per PR, each with its cost
  reported. Read [docs/costs.md](docs/costs.md) before any real run and add it to the spend log.
- **One source per history.** Never combine Takeout and API data into one series: the API's sleep
  comes from a newer algorithm, so a mix fakes a change. Daily metrics are stored per source.
- **No medical diagnosis or advice**, anywhere: agent output, mock replies or UI copy. The app
  describes patterns in the user's own data.
- **The LLM never computes statistics.** Numbers come from deterministic tools in
  `backend/app/analysis`; the agent chooses what to investigate and writes text that cites
  evidence ids.
- **No AI attribution.** No `Co-Authored-By` trailers or "generated by" lines in commits or PRs.
- **Keep the Expo SDK on the one Expo Go runs.** Expo Go on the App Store runs only the newest
  SDK, now 58, and testers use it: upgrade when Expo Go moves on (an older project no longer
  opens), never ahead of it.

## Workflow

`main` is protected: changes land only through a pull request whose `backend` and `mobile`
checks pass, and the rules apply to admins too. Branches are short-lived and deleted after merge.

1. **Branch from an up-to-date `main`**: `feat/…`, `fix/…`, `docs/…`, `ci/…`, `test/…`.
2. **Commit small and focused**, one logical change per commit, and push each commit as you go.
   Each commit should build and pass its checks on its own. Message: an imperative subject line
   ("Add trend tool", not "added stuff"), then a short body saying *why*.
3. **Verify before you push** (see below). Never push something you have not run.
4. **Open a PR** with: what changed, why, and **how it was verified** (commands run, tests added,
   what you looked at). Mention known limitations honestly.
5. **Merge only when everything is green and verified**: both CI checks pass, every check below
   was run, and the change was observed working. If anything is red, flaky, unverified, or you
   are unsure, **do not merge**: fix it, or stop and ask. Merge with a merge commit
   (`gh pr merge <n> --merge`); squash and rebase merges are disabled on purpose.
6. **After merging**, update local `main` and delete the local branch.

Never force-push to `main`, never bypass branch protection, never skip hooks or checks. If a check
fails for reasons outside your change, fix it in its own PR first.

## Verification checklist

Run what applies, from the repository root unless noted.

**Backend**

```bash
source .venv/bin/activate          # python3 -m venv .venv && pip install -e "backend[dev]" first time
cd backend && ruff check . && ruff format --check . && pytest -q
```

- New behavior gets tests, including the unhappy paths (bad input, missing data, malformed files).
- Statistical tests must not depend on one lucky seed: assert properties over many seeds
  (false-positive rate near alpha, unbiased estimates, interval coverage, power).
- When ingestion changes, also run it on the real local export (`Takeout/`, if present) and check
  the result against Fitbit's own values. Report only aggregates; never commit or paste
  personal values.
- When the API mapping changes, run `python -m app.sync compare --export Takeout` (needs a sign-in)
  and compare with the results recorded in `docs/metrics.md`.
- When the models change, add a migration (`alembic -c backend/alembic.ini revision --autogenerate
  -m "..."`); the tests fail if models and migrations drift apart.

**Mobile**

```bash
cd mobile && npm ci && npm run lint && npm run typecheck && npm test && npx expo-doctor
npx expo export --platform web     # the web build must still build
```

- For UI changes, run the app (`npm run web`, or `npx expo start` and open it in Expo Go) and look
  at every changed screen in **light and dark mode**. Click through the flow, including error
  and empty states, and check the browser console for errors. A scripted browser run (e.g.
  Playwright against `http://localhost:8081`) is a good way to prove a flow works.
- Add tests for logic (formatting, chart geometry, API contract behavior of the mock).

## Code conventions

- Match the surrounding code: naming, comment density, structure. Comments explain *why*.
- Backend: type hints, small pure functions, `ruff` clean (line length 100). Tools validate input
  and raise `ToolError`; ingestion raises `IngestError` instead of returning partial data.
- Mobile: TypeScript strict, Expo Router routes in `src/app/`, everything else outside it. Use
  `npx expo install` (not plain `npm install`) for Expo-managed packages. Colors come from
  `src/theme.ts`, both themes.
- When the API contract changes, update `types.ts`, the mock, `http.ts`, and the backend schema
  together.

### Known pitfalls

- `<Link asChild>` children need a single flattened style object: style arrays crash the app and
  pressed-state style functions are dropped on web.
- To go from a stack screen (e.g. `finding/[id]`) to a tab, use `router.dismissTo`: `push` and
  `navigate` stack a second copy of the tabs.
- TypeScript 6 does not load global types by default; test globals come from `"types": ["jest"]`
  in `mobile/tsconfig.json`.
- `CI=1 npx expo start` disables reloading: after changing app code, restart it (with `--clear`)
  before re-checking, or you will be looking at the old bundle.
- Run the API from the repository root with `.venv` active (`--app-dir backend`); from another
  folder or with the system Python it fails with `No module named 'app'`.
- Expo Go needs the phone and computer on the same network (or `npx expo start --tunnel`), and an
  Expo login on both.
- In the Takeout export, the legacy `Global Export Data` steps file is in UTC but its calories file
  is in local time; activity minutes come from Fitbit's daily totals, not `Activity Level`.
- Newer Takeout exports have **no** `Global Export Data` folder, and every nutrition value is "N/A".
  Live data comes from the API instead.
- Google Health API quirks: `sleep` returns nothing without a time filter; `steps` ignores
  `pageSize`; 64-bit numbers arrive as strings and durations as `"123s"`; the Active Zone Minutes
  cardio and peak sums are already doubled; daily roll-ups accept at most 90 days (14 for heart
  rate, active minutes and calories).
- Writing workouts: `displayName` and `metricsSummary` are required (empty is fine). Exercises are
  listed with a filter on `exercise.interval.civil_start_time` in local time **without** an offset;
  `total-calories` and `floors` cannot be listed, only rolled up. A range roll-up
  (`dataPoints:rollUp`, `HealthClient.rollup`) reproduces Fitbit's own workout summaries; see
  [docs/workouts.md](docs/workouts.md). Swim-length points also appear outside swims.
- Web-only hover: CI's React Native types have no `hovered` on Pressable state; use
  `isHovered(state)` and `canHover()` from `src/lib/platform.ts`, and show hover-only controls all
  the time on touch screens.
- Formatting: `npx prettier --single-quote --print-width 100`. Several older files are not
  Prettier-clean, so format whole files only when they were clean before; otherwise just your lines.
- A real Google write is a real entry in someone's Fitbit: test only with approval, then undo it
  and check it is gone (Google returns 404 for a deleted record).
- The Google OAuth app is in Testing mode: the sign-in expires after 7 days (`ReconnectNeeded`);
  run `python -m app.sync connect` again. Only listed test users can sign in.
- Postgres for this project is on port **5433** (`docker compose up -d db`); 5432 may be another
  Postgres on the machine.
- macOS may block reading `~/Downloads` from the terminal; move files into the project instead.

## When in doubt

Ask before: changing the architecture or API contract in a breaking way, adding a heavy
dependency, deleting data or branches you did not create, or anything outward-facing (deploying,
publishing, changing repository settings). Prefer stopping with a clear question over guessing.
